Job-discovery pipeline

I built a job-discovery workflow that brings API data into a common schema, removes duplicates and ranks relevant opportunities with local embeddings.

Working tool Produces a ranked digest for review, with a human step before anything is sent.
Fetch→Normalize→Deduplicate→Rank→Human review

Problem

Roles appear across different boards, with inconsistent fields, duplicates and changing availability. Discovery and application readiness are different problems.

Decision

Keep normalization and state deterministic, use models for relevance, and keep unread application questions visible for human review.

Implementation & ownership

I designed and built the workflow using Python, SQLite, API integrations and local models. The pipeline preserves source data and stops dependent stages when required upstream work fails.

Outcome

The system produces a ranked digest for review. It is a personal tool with a human review step. Application submission and hiring outcomes are outside this case study.

Inspect the workflow boundary

The pipeline preserves source records, normalizes fields, deduplicates postings, ranks relevance and produces a digest for review. A failed required stage prevents dependent work from continuing.

Fetch → Normalize → Deduplicate → Rank → Review
Required stage failure → Stop dependent stages
