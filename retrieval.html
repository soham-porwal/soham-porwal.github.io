Retrieval evaluation Independent brain-tools + eval-lab Evaluation · Aug 2026

The search “improvement” I rolled back.

A more diverse set of search results sounded better. A paired evaluation showed that it displaced relevant notes. I retained the simpler baseline.

Problem

A personal knowledge corpus contained many more notes from some sources than others. Those sources could dominate retrieval even when a broader result set seemed desirable.

Decision

Test source caps and diversity selection against plain vector search, with acceptance criteria fixed before the comparison. Better source balance alone would not justify worse retrieval.

Implementation & ownership

I developed the retrieval and evaluation workflow and owned the test decisions and interpretation. The harness records the query set, configurations and index fingerprints so the two arms can be compared.

Outcome

Source diversity improved, but recall declined. The change failed the acceptance rule and was reverted. The result is specific to this corpus and query set; a promising setting found in a later sweep remains a hypothesis for fresh evaluation.

Method note: the reference sets were oracle-derived, not fully human-labeled. This comparison supports a decision on this corpus; it does not establish a universal ranking of retrieval methods.

Recompute the recorded result

The download includes anonymous paired recall scores and a standard-library scorer. It reproduces the means shown above without exposing queries or corpus content. It recomputes the summary, not the original retrieval run or the reference judgments.

python retrieval_eval/scorer.py
python retrieval_eval/scorer.py --synthetic

The synthetic example is separate and demonstrates the metric calculation; it is not evidence for the historical result.
