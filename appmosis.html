Integrating brokerage data into a portfolio AI feature

At Appmosis, a San Francisco fintech startup, I led specification and launch coordination for an AI feature that answers questions using a user’s portfolio holdings. The work combined brokerage data integration, prompt design and pre-release validation.

6–8 weeks From specification to general availability, in partnership with engineering.
Brokerage APIs→Common data model→Relevant holdings→Grounded answer

Problem

Brokerage APIs describe positions differently. Inconsistent inputs could corrupt portfolio reporting and give an AI feature unreliable context.

Decision

Normalize each broker’s JSON into a common schema and upsert positions in GCP Spanner by account and symbol. At question time, query only the relevant holdings and format a compact context block. The answer uses portfolio state as of the last sync.

My contribution

I defined the context assembly logic and prompt architecture, built Python transformations for 5+ brokerage APIs, and coordinated delivery with engineering. I also built dashboard validation checks and used SQL to measure launch activity.

Outcome

The feature reached general availability in 6–8 weeks. Before release, I investigated sector allocations that failed to sum correctly and traced the problem to null prices on halted stocks. The issue was fixed before it reached production.

Related work sample: brokerage normalization

I developed this separate, AI-assisted demonstration using public vendor examples and synthetic edge cases. It covers instrument identification, options units, reconciliation and repeat ingestion. It is not the Appmosis implementation and contains no employer code or data.

python -B checkpoint.py

Requires Python 3.12 or newer. Extract the ZIP and run this command inside the brokerage-normalization folder. The checkpoint runs the tests and checks reconciliation, repeat ingestion and database integrity. The sample runs offline with Alpaca and Plaid examples and a Fidelity-shaped test CSV; it does not connect to live accounts.
